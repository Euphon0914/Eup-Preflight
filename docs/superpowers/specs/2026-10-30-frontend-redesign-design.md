# Eup Preflight 前端视觉与动效升级 —— 设计文档

日期：2026-10-30 · 状态：待评审

## 1. 目标与约束

**用途**：参赛展示。主要场景是作者在自己电脑上现场演示或录屏，桌面大屏为主（Chrome / Edge）。

**成功标准**

- 评委第一眼有记忆点：首屏、品牌色、三个关键时刻的动效（导入 → 分析、体检结论揭晓、一键修复前后）。
- 演示全程流畅，不因动效拖慢视频分析：同一段 2 分钟视频，“高级 › 每一步耗时”里的分析耗时比改动前慢不超过 5%。
- 现有功能、检查逻辑、处理逻辑完全不变。

**约束**

- 纯前端、无构建步骤、离线可用：新增的第三方库和现有库一样放进 `vendor/`，由 `scripts/download-vendor.sh` 按固定版本下载。
- 尊重系统“减少动态效果”设置。
- 浅色 / 深色模式都要完整适配；演示推荐深色。

**范围之外**：画面遮挡、封面页的叠加动画；校准页布局；任何检查 / 处理逻辑。

## 2. 技术选型

- **动画库**：Motion（npm 包 `motion`，MIT 许可），固定版本 **14.2.0**（2026-10-13 发布），使用单文件 UMD 版 `dist/motion.js`（约 150 KB，挂到 `window.Motion`）。放在 `vendor/motion/motion.js`，在 `index.html` 里用普通 `<script>` 先于 `js/main.js` 加载。
- **首屏背景**：原生 Canvas 2D，不用 WebGL。
- 其余用 CSS（变量、keyframes、transition）。

## 3. 首屏

**何时出现**

- 没有载入视频时，首屏占满工作区（顶栏不变，`.workspace` 隐藏）。
- 点顶栏 logo 回到首屏；若已载入视频，首屏显示“继续检查 <文件名>”按钮，点它回到工作台，当前视频和结果都保留。
- 打开页面时自动载入上次视频的现有行为不变（载入完成后直接进入工作台）。演示前可在「技术体检 › 历史」里关掉自动载入。

**布局**（宽屏两栏，窄屏上下堆叠）

- 左：一行小字“抖音 / TikTok 发片前检查 · 本机处理，不上传”；大标题“发片之前，先 Preflight 一遍”，其中 Preflight 用品牌色底高亮；大拖放区，内含“选择视频”主按钮（品牌色）和“没有素材？生成一段测试视频”链接。整页仍可直接拖入视频或图片（图片照旧交给封面适配）。
- 右：手机框演示动画，循环播放：扫描线自上而下扫过 → 界面遮挡区域依次浮现 → 一处问题位置闪烁 → 出现对勾。用 DOM + Motion 实现，不用视频文件。
- 下：三张能力卡片——技术体检（规格不对一键修复）、画面遮挡（字幕会不会被按钮挡）、封面适配（各比例裁切预览）。
- 背景：Canvas 上几团缓慢漂移的柔光，其中一团是品牌色，轻微跟随鼠标；玻璃透出流动的光。

**Canvas 规则**

- 只在首屏可见时运行；导入视频、首屏隐藏、页面切到后台（`visibilitychange`）时停止 `requestAnimationFrame`。离开首屏后释放（清空画布）。
- 设备像素比上限 1.5，帧率上限 30。
- “减少动态效果”下只画一帧静态画面。

**首屏 → 工作台过渡**（约 0.6 秒，弹簧收尾）

- 拖放区缩小并飞到左栏视频卡片的位置（FLIP：记录首屏拖放区位置 → 显示工作台 → 从旧位置动画到新位置）。
- 三张能力卡片收拢到左栏步骤导航的位置。
- 右侧面板自下而上浮现，随后接“开始分析”动效。
- 顶栏副标题（“Preflight for 抖音 / TikTok · …”）只在工作台显示，首屏由大标题承担。

## 4. 视觉系统

**品牌色：霓虹柠檬**

| 变量 | 浅色模式 | 深色模式 | 用途 |
|---|---|---|---|
| `--brand` | `#C8F03C` | `#C8F03C` | 填充 |
| `--on-brand` | `#1A2600` | `#1A2600` | 品牌色底上的文字 / 图标 |
| `--brand-ink` | `#5A7A00` | `#C8F03C` | 需要品牌色文字时 |
| `--brand-glow` | `rgba(200, 240, 60, .35)` | `rgba(200, 240, 60, .45)` | 光晕、拖尾 |

**用法规则**

- 品牌色只表示“行动”和“进行中”：主按钮（选择视频、一键修复、下载）、选中步骤的图标底、进度条和扫描线、键盘焦点框、logo 色块、首屏标题高亮。
- 状态色不用品牌色：通过 / 警告 / 不通过仍为绿 / 橙 / 红。“通过”的绿色往偏蓝方向调（浅色约 `#1F7A5C`，深色约 `#4FD1A5`，实施时以对比度达标为准），并在状态标签里加对勾图标，不只靠颜色区分。
- 同一块区域内最多一个品牌色实心元素。其余界面保持黑白灰，`--accent`（黑 / 白）仍用于次要强调。

**玻璃细化**（只用 CSS，不对 `backdrop-filter` 做动画）

- 顶部内高光：大玻璃块上边缘一条细的内高光。
- 磨砂颗粒：一层极淡的噪点纹理（内联 SVG `feTurbulence`，数据 URI）。
- 鼠标反光：鼠标在大玻璃卡片上移动时，一块淡反光跟随（JS 只写 CSS 变量 `--mx` / `--my`，由 `::after` 的径向渐变渲染）。只在 `(hover: hover) and (pointer: fine)` 下开启。
- 两层阴影：贴近的接触阴影 + 大而柔的投影。

**文字层级**

- 右侧大标题 28px → 32px，标题用 SF Pro Display。
- 体检结论里的计数做成大号数字（`tabular-nums`），配合数字滚动。

**Logo**

- 暂用纯品牌色圆角方块占位，不含图形。顶栏、页脚、四个页面（`index.html`、`calibrate.html`、`licenses.html`、`webcodecs-test.html`）的网页图标统一替换。色块的尺寸和圆角集中在 `base.css` 的 `.logo` / `.sign-mark` 里，以后换正式 logo 只改这里和 favicon。

**动效参数**（集中定义，CSS 变量 + `motion.js` 常量各一份，数值一致）

- 时长：快 0.18 秒、标准 0.32 秒、强调 0.6 秒。
- 缓动：`cubic-bezier(.2, .8, .2, 1)`（标准出场）。
- 弹簧：`{ stiffness: 380, damping: 30 }`（按钮、滑块）；`{ stiffness: 220, damping: 26 }`（大块过渡）。实施时按手感微调，只改这一处。

## 5. 三个关键时刻的动效

### 5.1 导入视频 → 开始分析

1. **拖着文件进入页面**：页面四周亮起品牌色光边（`body` 上的类控制一个固定定位的边框层）；拖放区微微放大。松手时拖放区回弹一下。
2. **首屏 → 工作台**：见第 3 节。
3. **分析中**：
   - 左栏视频卡片上一条品牌色扫描线上下往返扫动，下方带淡拖尾（纯 CSS keyframes，只动 `transform`）。
   - 右侧进度区从“一行文字 + 进度条”改为“阶段清单 + 进度条”：阶段依次为 读取参数 → 加载 ffmpeg 核心（已加载过则跳过）→ 补充探测帧率（仅读不到帧率时出现）→ 分析声音（无音轨时跳过），与 `media.js` 现有各段 `showTask` 一一对应。当前阶段转圈，完成打勾。进度条为品牌色，最前端有光点。
4. **后台检查**：画面遮挡、封面在后台运行时，左栏对应步骤图标外有一个旋转环；完成后变成数字角标并弹一下。

### 5.2 体检结论揭晓

1. 进度区收起，结论卡片从进度区的位置展开。
2. 结论图标（对勾 / 感叹号 / 叉）改为 SVG，用描边动画一笔画出。
3. 不通过 / 警告 / 通过三个数字从 0 滚动到实际值。
4. 问题列表逐条滑入，相邻间隔 40 毫秒，按严重程度排序后的顺序出现。
5. 总报告页使用同一套揭晓动画，时长减半。

### 5.3 一键修复前后

1. **打开弹窗**：从被点击的按钮位置展开（以按钮矩形为起点缩放 + 淡入）。
2. **处理中**：弹窗里显示处理阶段清单——检查处理方式 → 处理声音 → 编码视频 → 合并音视频 → 复检。阶段名与 `fixes.js` 现有的各段 `showTask` 一一对应，实际走不到的阶段（例如只处理声音时没有“编码视频”）不显示。当前阶段转圈，完成后变品牌色对勾。
3. **完成**：
   - 原来的警告 / 不通过标记依次翻转成“通过”（只翻转实际变好的项）。
   - 左栏视频参数中变化的值，以“旧值划掉 → 新值”的形式动画替换。
   - 下载按钮出现时带一次品牌色光晕脉冲。
4. **前后对比**：对比页的截帧从左右并排改成同一位置叠放，中间一条可拖动的分隔线（拖动时为品牌色），左边看处理前、右边看处理后。窄屏上同样可用（支持触摸拖动）。**优先级最低，排在最后实施**。

### 5.4 全局小动效

- 切换步骤：右侧内容淡出淡入并带轻微位移；左栏选中背景（一个独立的滑块元素）滑到新步骤上。
- 按钮按下轻微缩小后回弹；分段控件的选中块滑动过去。
- “减少动态效果”下：所有动效退化为 0.15 秒以内的淡入淡出，扫描线、Canvas、数字滚动都关闭（直接显示最终值）。

## 6. 代码结构

### 6.3 防止重复播放

现有模块在每次 `notify` 时用 `innerHTML` 整块重渲染（例如声音分析进度每更新一次）。动效必须由“状态变化”触发，而不是由“重新渲染”触发：

- `motion.reveal(el, key)` 把上一次的 key 记在元素的 `dataset` 上；key 相同则直接显示最终状态，不播放。
- 揭晓类动画的 key：`文件名 + 文件大小 + 平台 + 结论 + 是否仍在分析`。换视频、切平台、修复完成、声音分析结束都会产生新 key。
- 数字滚动同理：数值不变不滚动。

### 6.4 兜底

- Motion 未加载（`vendor/` 缺文件、加载出错）：`motion.js` 所有函数立即把元素放到最终状态；页面功能完全正常，只是没有动画。控制台打印一条警告。
- 不支持的浏览器（Safari / Firefox）：沿用现有兼容提示；动效能用多少用多少，不额外处理。

## 7. 性能

- 所有动画只改 `transform` 和 `opacity`；不对 `backdrop-filter`、`filter`、尺寸属性做动画。
- 分析和处理视频时 Canvas 已停止。
- 鼠标反光只写 CSS 变量，节流到每帧一次。
- 验收：同一段 2 分钟视频，在改动前后各跑一次导入分析和一次一键修复，比较“高级 › 每一步耗时”，分析和处理耗时增幅不超过 5%。

## 8. 验证

项目没有自动化测试，用浏览器预览逐项检查并截图：

1. 首屏：布局、Canvas 背景、手机框演示循环、拖入光边、回到首屏、继续检查。
2. 导入过渡、分析中（扫描线、阶段清单）、后台检查旋转环与角标。
3. 结论揭晓：描边、数字滚动、列表依次出现；声音分析进度更新时不重播。
4. 一键修复全流程：弹窗展开、阶段清单、翻转、参数旧值 → 新值、下载脉冲。
5. 对比页拖动分隔线（鼠标与触摸）。
6. 浅色 / 深色、窄屏（375 px）、开启“减少动态效果”。
7. 临时移走 `vendor/motion/motion.js`，确认页面照常可用。
8. 性能对比（第 7 节）。

## 9. 实施顺序

1. 基础：下载 Motion、`motion.js`、品牌色与动效变量、logo 色块、玻璃细化。
2. 首屏与 Canvas、首屏 → 工作台过渡。
3. 导入 → 分析：拖入光边、扫描线、阶段清单、后台检查状态。
4. 结论揭晓（体检 + 总报告）。
5. 一键修复：弹窗展开、阶段清单、完成效果。
6. 全局小动效：步骤滑块、切换过渡、按钮与分段控件。
7. 对比分隔线（可选，时间不够时不做）。
8. 文档与许可：README、THIRD_PARTY_NOTICES、licenses.html。
9. 全面验证与性能对比。
